# Лабораторная работа по ООП: Оргструктура и согласование документов

**Вариант 24 (Повышенный уровень)**  
**Стек:** Java 21, Maven, JUnit 5

---

## 1. Описание предметной области
Проект реализует объектно-ориентированную модель организационной структуры компании и систему гибкого согласования документов по полиморфным правилам.

- **Оргструктура:** представлена в виде N-арного дерева подразделений (`Department`), поддерживающего вложенность любой глубины, назначение руководителей и учет сотрудников (`Employee`) с ролями (`Role`).
- **Документооборот:** документы (`Document`) проходят по цепочке шагов (`ApprovalStep`), определяемых правилами (`ApprovalRule`).
- **Безопасность:** попытка согласовать чужой шаг или изменить закрытый документ пресекается выбросом собственного исключения (`ApprovalException`).

---

## 2. Архитектура и структура классов

### Пакет `model` (Оргструктура):
- `Department` — узел дерева подразделений. Поддерживает поиск начальника на N уровней вверх (`findManagerAbove`) и рекурсивный сбор сотрудников вглубь (`getAllSubordinates`).
- `Employee` — класс сотрудника. Идентифицируется по `id` (контракт `equals/hashCode`). Поддерживает назначение отпуска и заместителя.
- `Role` — перечисление должностей с полями.
- `Substitution` — `record` для замещения сотрудника на интервале дат.

### Пакет `document` (Документы):
- `Document` — документ со статусом, автором, датой создания и уникальным номером.
- `DocumentStatus` — перечисление состояний (`DRAFT`, `UNDER_PROCESSING`, `APPROVED`, `REJECTED`).

### Пакет `approval` (Маршрутизация и правила):
- `ApprovalRule` — `sealed interface` (закрытая иерархия Java 21) с полиморфным методом `findApprover(Document)`:
    - `DirectManagerRule` — непосредственный руководитель (с подъемом на уровень выше, если автор сам начальник).
    - `DepartmentHeadRule` — руководитель подразделения автора.
    - `RoleBasedRule` — поиск сотрудника с заданной ролью во всей компании.
- `ApprovalRoute` — движок маршрута. Управляет переходом по шагам, аудитом истории и статусами.
- `ApprovalStep` — шаг маршрута с дедлайном (`Period`) и назначенным лицом.
- `ApprovalRecord` — неизменяемая запись (`record`) в истории согласования.

### Пакет `exception`:
- `ApprovalException` — собственное непроверяемое исключение (`RuntimeException`).

## 3. Особенности повышенного уровня
1. **Замещение на период отпуска:**  
   На интервале дат отпуска (`startDate` ... `endDate`) право подписи автоматически переходит назначенному заместителю. Вне интервала — возвращается исходному руководителю.
2. **Эскалация по сроку:**  
   Если шаг не согласован за отведенный период времени (`Period.ofDays(...)`), метод `escalateIfOverdue` автоматически переназначает шаг на вышестоящего руководителя (`findManagerAbove(1)`).
3. **Инкапсуляция:**  
   Изменяемое состояние защищено — все методы возвращают `Collections.unmodifiableList`.
